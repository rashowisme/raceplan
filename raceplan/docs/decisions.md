# Decisions

Short log of decisions made autonomously (date — decision — reason).

- **2026-10-31 — App lives in `raceplan/`, git repo is the parent folder.** The brief was committed as `raceplan/…` in `raceplan-starter/`; kept that layout instead of moving the repo root.
- **2026-10-31 — Next.js 16.4 without `cacheComponents` / `partialPrefetching`.** create-next-app enables these experimental flags; next-intl's static rendering (`setRequestLocale`) is simpler without them and the app is mostly client-side (form, localStorage, PDF).
- **2026-10-31 — `proxy.ts` instead of `middleware.ts`.** Next 16 renamed the convention; next-intl's `createMiddleware` is exported from `src/proxy.ts`.
- **2026-10-31 — Replaced the `cn` npm package with the classic `clsx` + `tailwind-merge` helper.** The shadcn CLI pulled a new 3.5k-line compiler package for a 2-line helper; both libs it replaces were already in the stack. `shadcn` is a dev dependency (only its CSS is imported at build time).
- **2026-10-31 — Extra dev deps:** `@vitejs/plugin-react`, `jsdom`, `@testing-library/react|dom` (component tests), `eslint-config-prettier` (Prettier + ESLint), `tw-animate-css` + `radix-ui` (pulled in by shadcn/ui components).
- **2026-10-31 — Engine purity enforced by ESLint** (`no-restricted-syntax` on `Date.now()`, `new Date()`, `Math.random()`, banned browser globals and React/Next imports in `src/engine`).
- **2026-10-31 — Weekdays are string codes `mon…sun`; dates are ISO `YYYY-MM-DD` strings** in the engine contract, so plans serialize to JSON/localStorage losslessly and are timezone-free.
- **2026-10-31 — Elevation is shown in feet when the mile unit is selected.** Matches what imperial users expect; conversion still only happens in `lib/units.ts`.
- **2026-10-31 — Cutback vs 10% rule.** Week-over-week increases are measured against the last _full_ (non-cutback) week; the week after a cutback returns to the pre-cutback level and never above it. Measuring against the cutback week itself would make every cutback a −22% / +28% saw-tooth that violates §7.2 literally. The property tests check exactly this rule.
- **2026-10-31 — Progression follows what was planned, not targets.** Each week's increase is computed from the previous week's _planned_ volume, so caps (easy run ≤ long run, minimum run lengths) can never cause a hidden jump. Partial first weeks (plan starting mid-week) use the full-week target as reference and only schedule the share of runs that fall in the plan.
- **2026-10-31 — Two-run weeks: even split instead of the 30/40% long-run share.** With only 2 available days (or a partial week with 2 runs), "long run ≤ 40% of the week" is only possible if the other run is longer than the long run. We cap both runs at an even 50/50 split — the least concentrated split possible — and warn `few_days_available` for half/marathon. ✅ Confirmed by owner (2026-10-31); generalised below.
- **2026-10-31 — At least 2 available days required** (schema). A single weekly run is not a training plan and makes the long-run rules meaningless.
- **2026-10-31 — Stricter-than-spec choices** (all safe direction): tiny weeks grow at most +50% (spec allows +3 km, i.e. 3 → 6 km); shin splints / stress fracture → 5% ramp and +2 km allowance; long runs ≤ 2 days before the race are dropped (3 days at 50+), and the day before the race is always rest (optional shakeout for experienced runners); quality sessions are downgraded to easy runs if a week would miss the 75% easy-time floor.
- **2026-10-31 — Taper granularity is whole weeks** (7 → 1, 10 → 1, 14 → 2, 21 → 3 weeks; race week included). Taper week 1 is −25% from the last full week, later taper weeks −25% from the previous one; race week is 2–3 short easy runs + strides, ≤ 80% of the previous week (race itself excluded from training volume and from the max-volume rule).
- **2026-10-31 — Race volume is not training volume.** The race-day workout is excluded from `plannedVolumeM`, otherwise a marathon would break the user's max in race week.
- **2026-10-31 — Time trial for beginners in week 3**, not week 2, so the "strides only in the first 2 weeks" beginner rule holds. Non-beginners get it in week 2. Optional, effort-based.
- **2026-10-31 — Effort-only plans still estimate durations** using assumed paces by level (VDOT 30/38/45); these never appear as targets.
- **2026-10-31 — Peak volume = min(user max, level target, progression).** A runner already above the level target (e.g. 100 km/week for a 5K) is brought down to the target from week 1, per §7.8.
- **2026-10-31 — Form renders after hydration.** The wizard restores a localStorage draft, so it mounts client-side only (skeleton during SSR) instead of patching state in an effect. Per-step validation uses Zod step schemas; on submit the profile is validated again with the engine's shared `runnerProfileSchema` + `validateProfile`, and engine issues are mapped back to form fields.
- **2026-10-31 — Form keeps values in the user's units** (strings as typed). Switching km/mi mid-form converts the typed numbers (2-decimal precision so round-trips are stable); `toProfile` converts to metric — still only via `lib/units.ts`.
- **2026-10-31 — v1 keeps one "current" plan** (`id = "current"`) in the localStorage repository; the repository already supports several plans for the future account feature.
- **2026-10-31 — Unit preference defaults to km** for both locales and is remembered in localStorage.
- **2026-10-31 — Plan styles share one engine and all safety rules; they only change session menus.** VDOT-style follows Daniels' phase order (R → I → T/race pace). 80/20 uses Z3 sessions (intervals, hills), keeps long runs easy, and enforces ≥ 80% easy time (builder budget 81%, checker 80%). Z1–Z3 labels are mapped onto the same Daniels paces.
- **2026-10-31 — Injury substitutions respect preferences too** (e.g. the plantar-fasciitis hill swap never picks a disliked session). A disliked tag can only appear together with a `preference_unmet` warning (property-tested).
- **2026-10-31 — PDF uses react-pdf's built-in Helvetica** (no font download, no network). All message strings are tested to fit its WinAnsi character set. Landscape A4: summary page + week rows with full workout titles; disclaimer and page numbers on every page. The renderer is lazy-loaded on click.
- **2026-10-31 — Taper sharpening falls back to shorter race-pace reps** (½ then ¼ of the normal rep) before any other session, so taper weeks keep "short sharp efforts at race pace" (§11). Recovery runs never get strides.
- **2026-10-31 — Trail long runs: time on feet, distance as flat-equivalent.** The progression still works in (flat-road) km so all volume rules apply unchanged; the long run is prescribed in whole 5-minute blocks whose estimated flat distance never exceeds the target. Climbing targets grow with the phase (base 45% → specific 100% of the race's D+/km) and are capped at the race's total D+.
- **2026-10-31 — Trail = no flat race pace.** Race-pace sessions become tempo, race-pace long runs become progressive, taper sharpening is a short fartlek, and race day is effort-based (duration estimated from the predicted time over the real distance). Steep races (> 50 m D+/km) get power-hiking inside uphill repeats; knee/IT band history removes downhill practice.
- **2026-10-31 — Long-run cap smoothed below 30 km/week (builder only).** Between ~22 and 30 km/week the long run is also limited to 9 km (30% of 30 km), so the long run never drops when weekly volume crosses 30 km (spec allows 40% below, 30% above — a visible 11 → 9 km drop for real runners). The safety checker keeps the exact spec rule.
- **2026-10-31 — Removed unused `date-fns` and `@hookform/resolvers`** and unused generated shadcn components. Engine dates use timezone-free ISO helpers (`src/engine/dates.ts`, weeks start Monday); UI dates use `Intl.DateTimeFormat` in UTC. Validation is per-step Zod `safeParse` rather than a resolver.
- **2026-10-31 — Deployment config:** `vercel.json` with `regions: ["cdg1"]`, baseline security headers in `next.config.ts`, no env vars. Nothing deployed (owner's call).
- **2026-10-31 — Dark mode without a library.** A one-line inline head script (no next-themes dependency) sets the `dark` class before paint to avoid a light flash; default is "system". Brand blue kept in dark mode (lighter, dark text on it). The PDF is always light, since it's meant for printing.
- **2026-10-31 — Long-run share raised to 33% (owner decision).** The owner asked for slightly longer long runs: §7.6 now reads 33% (was 30%) above 30 km/week; 40% below is unchanged. Peak long runs grow ~1–3 km (e.g. marathon 25.5 → 28 km); race caps and the 3 h cap are unchanged.
- **2026-10-31 — Even-split rule generalised to n runs.** The long run is also the week's longest run, so with n runs it can never be below 1/n of the volume. The cap is max(share, 1/n): 2 runs → 50% (as before), 3 runs ≥ 30 km → 33.3% (just above 33%). Without this, 3-day runners above 30 km/week were shrunk pass after pass (a 50 km/week runner got ~25 km). When the even split binds, the long run is shortened once and the other runs may stay up to one rounding step (≤ 500 m road, one 5-min block trail) longer.
- **2026-10-31 — Time trial result: keep started weeks, rebuild the rest.** Applying paces to the existing workouts would change their estimated distances (effort-only plans estimate with level-based paces), which could break the ramp rules. Instead the plan is rebuilt from the original generation day and start date, with the builder adopting the already-started weeks as-is and continuing the progression from their real volumes. The safety checker validates the combined plan (property-tested). No penalty on the time trial (solo efforts aren't optimistic); Riegel per §3.5.
